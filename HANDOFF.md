# Sieve — handoff notes

State as of 2026-08-29. Everything in the approved plan (phases 1–4) is implemented and green.

## What's verified

- `xcodebuild build` and `test` pass: 20 tests in 5 suites (scan diff, file enumeration, PCM hashing incl.
  WAV≡AIFF≡extra-chunk equivalence, levels/clipping math, waveform round-trip, FTS/filters/folder tree,
  hash-keyed annotations surviving a move, duplicate grouping, trash/move reconciliation via a fake FS).
- Manually checked in the running app on 9 generated fixtures: indexing + progress, sidebar folder tree,
  table with waveforms and clip indicators, inspector (full-res waveform, levels, metadata, rating, tags,
  notes, reveal), auto-preview, Duplicates view grouping a WAV and its AIFF conversion.
- **Not exercised in the live app:** the actual Trash/Move buttons (logic is unit-tested; the UI path was only
  eyeballed). First thing worth trying by hand on a throwaway folder.

## Design decisions to keep

| Decision | Reason |
|---|---|
| Xcode project generated by `xcodegen` from `project.yml` | reproducible, terminal-buildable; don't commit the `.xcodeproj` |
| GRDB (only dependency) rather than SwiftData | FTS5 search, fast batch inserts, `ValueObservation` for live SwiftUI updates |
| Hash decoded PCM, not file bytes | duplicates across containers/metadata chunks; whole-file hash only as fallback |
| Annotations keyed by content hash | tags/ratings follow renamed/moved files; identical copies share them (shown as "N identical copies") |
| Scans never delete rows | unplugged drives → `unavailable`, deleted files → `missing`; user purges explicitly |
| Only `FileOperator` writes to disk | single audited path with pre-checks, confirmation sheet, op log |
| BPM/key from filename only | audio-based detection is real DSP work; columns already exist for it |

## Known rough edges / next steps

1. **Default "Keep" pick** is shortest path; you may prefer "prefer WAV/AIFF over lossy" or "oldest".
   `DuplicateGroup.defaultKeeper` is the one place to change.
2. **Waveform zoom** regenerates the whole file at `1024 × zoom` buckets (max 16 384) and scrolls; a true
   viewport-range regeneration (`WaveformGenerator.summary(range:)` already supports it) would be cheaper on long files.
3. **Drag samples onto sidebar tags** is wired (`.draggable(row.id)` → `.dropDestination` on tag rows) but was
   not tested by hand.
4. **Stale bookmark "relink" flow** is not built: if a drive is reformatted the root just shows as unavailable.
   Plan: match by `root.volumeUUID` + name and let the user re-pick the folder.
5. **NAS timeouts**: reachability check is synchronous inside the scan actor; a stalled SMB mount will block that
   root's scan task (not the UI). Add a timeout race if it bites.
6. **Near-duplicate detection** (same audio, different sample rate/bit depth/trim) is out of scope for v1.
7. Some AppleScript-driven UI automation was attempted for smoke tests; SwiftUI list-header buttons don't expose
   accessibility names, so don't bother — screenshot-and-eyeball is the working loop.
8. Distribution needs a Developer ID; current builds are ad-hoc signed (`CODE_SIGN_IDENTITY: "-"`).
